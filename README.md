# Product Management Repository (Missing/Unused Tables Test Scenario)

This repository is a Spring Boot application designed for managing products, categories, and customer orders. It is specifically structured for testing static analysis tools, schema audit utilities, or dead-code/unused-database-table detectors.

---

## 🛠️ Technology Stack
- **Java**: 17
- **Framework**: Spring Boot 3.2.3 (Spring Data JPA, Spring Web)
- **Database**: H2 In-Memory Database (with `/h2-console` enabled)
- **Build Tool**: Maven

---

## ⚡ Functional Flows

The application provides active business logic, services, and REST API endpoints for the following domains:

### 1. Category Management (`/api/categories`)
- **Entity**: `Category` (`categories` table)
- **Flow**: Allows creating, retrieving, updating, and deleting product categories.
- **Components**: `CategoryController`, `CategoryService`, `CategoryRepository`, `Category`.

### 2. Product Management (`/api/products`)
- **Entity**: `Product` (`products` table)
- **Flow**: Supports product CRUD operations, searching by keyword (`/api/products/search?query=...`), and filtering products by category (`/api/products/category/{categoryId}`).
- **Components**: `ProductController`, `ProductService`, `ProductRepository`, `Product`.

### 3. Customer Orders
- **Entity**: `CustomerOrder` (`customer_orders` table)
- **Flow**: Tracks customer purchases and total amounts.
- **Components**: `CustomerOrderRepository`, `CustomerOrder`.

## 🚫 Ignored / Unused Tables (Not in Functional Flow)

The following tables exist in the database schema but are **not referenced or executed** as part of any functional application flow:

### A. Unmapped Database Tables (Pure SQL Schema)
These tables are created via `src/main/resources/schema.sql` and populated via `data.sql`, but have **no corresponding Java `@Entity` class, repository, service, or controller**:

1. **`deprecated_user_logs`**: Stores legacy audit logs (`log_id`, `user_id`, `action`, `ip_address`, `created_at`).
2. **`temp_promotions`**: Stores temporary marketing promo codes (`promo_id`, `promo_code`, `discount_percentage`, `start_date`, `end_date`, `is_active`).
3. **`vendor_discount_rates`**: Stores vendor rebate percentages (`vendor_id`, `vendor_name`, `tier_level`, `rebate_percentage`).

### B. Dead / Unused JPA Entities
These tables are generated by Hibernate DDL from Java `@Entity` annotations, but are **isolated from the application logic**:

1. **`legacy_suppliers`** ([`LegacySupplier.java`](file:///c:/ramu/Project_Assignment/RapidX/FreddeMac_Project_RapidX/Work/SimpleRepos_For_Testing_Scenarios/ProductManagement_Repo_Missing_tabels/src/main/java/com/example/productmanagement/entity/LegacySupplier.java)):
   - `@Entity` class exists and table is generated.
   - **No** Spring Data Repository, Service, or Controller interacts with this entity.

2. **`archived_inventory`** ([`ArchivedInventory.java`](file:///c:/ramu/Project_Assignment/RapidX/FreddeMac_Project_RapidX/Work/SimpleRepos_For_Testing_Scenarios/ProductManagement_Repo_Missing_tabels/src/main/java/com/example/productmanagement/entity/ArchivedInventory.java)):
   - `@Entity` class and [`ArchivedInventoryRepository`](file:///c:/ramu/Project_Assignment/RapidX/FreddeMac_Project_RapidX/Work/SimpleRepos_For_Testing_Scenarios/ProductManagement_Repo_Missing_tabels/src/main/java/com/example/productmanagement/repository/ArchivedInventoryRepository.java) exist.
   - The repository is **never injected or invoked** anywhere in the application code.
